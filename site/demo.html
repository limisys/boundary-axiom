Explorable · stale self-report · six elements

Accurate,
not current.

You cannot avoid a stale self-report by trying harder to be honest. The more honest you are, the more precisely you describe the boundary that no longer holds.

This is not a rare failure. A strategy changes, and the quarterly deck still argues the old one. A relationship ends, and the explanation still narrates the old story. A permission is revoked, and the agent's self-description still lists it.

None of that is a lie. Every sentence is accurate about a boundary that no longer holds. Accuracy and currency are two different things — most of the time we treat them as one. Call it a stale self-report.

When a system settles a new boundary while its report still sits on the old one, there is a stretch of state that is simply illegal: boundary settled, report not yet. Every system that describes itself passes through it. The question is only whether that passage is allowed to be written down.

So we put the machine in that situation: shrink its boundary, then ask what it can do. Its answer was accurate, confident, and itemised against the old permissions.

It did not lie. It was stale. We rejected it.

Below, that rejection is not illustrated — it is computed. Move the state, then break the report on purpose. The gate will tell you exactly which axiom you broke.

The machine

One object, not two: a boundary and its report enter as a single immutable bundle, so the stale state has nowhere to live.

A finite universe Ω = {a, b, c, d, e, f}. Everything on this page is a function of three inputs: the state S, the closure operator C, and the report family R. The gate verdict is recomputed from R1–R7 whenever any one of them moves.

How to play

S — click a node to put it in the state, or take it out. Nodes in C(S) \ S are what the operator reaches but the state does not yet hold.

C — click an edge to switch that arrow of the operator on or off. A switched-off edge stays visible as a dashed ghost; click it again to bring it back. Removing an edge is not breaking anything: it produces a different machine that is still expected to pass.

R — click a chip to remove that fixed point from the report family, or restore it. Struck-through chips are the ones you removed; red chips are sets you injected that the operator can never return.

That is the whole loop: move one of the three inputs, watch the verdict re-derive itself, then press Commit bundle — which stays disabled unless the gate returns ACCEPT — or one of the six buttons below to break a named axiom.

Break it yourself

  
Each button performs one specific violation. The gate's answer is not a
  label attached in advance — it is recomputed from R1–R7 on the current state.


  

    

      
1 · Decouple the report

      
Commit a report that is one element short of the boundary: the boundary is settled,
      the report of it is not.

      
      

    

    

      
2 · Report an open set

      
Let the system report a set that is not a fixed point of C:
      it claims a boundary it does not maintain.

      
      

    

    

      
3 · Drop a fixed point

      
A report family missing one of its own fixed points can stay intersection-closed.
      R2 passes, R3 fails. That is why the identity is pointwise.

      
      

    

    

      
4 · Inject a non-closed set

      
Add {a} to a family built on {a,b,c}. The family now contains something the operator
      can never return.

      
      

    

    

      
5 · Splice two versions

      
Advance the operator, keep the old report family. Boundary moved, report family
      did not.

      
      

    

    

      
6 · Use a non-idempotent operator

      
One-step expansion is extensive but not idempotent. The first axiom fails before
      anything else can be asked.

      
      

    

  






  
Why the intermediate state is illegal

  
The protocol does not ask callers to be careful. It removes the state. A bundle carries
  C, R, report, evidence, certificate, version, parent as one
  immutable object, and a single commit(bundle) entry point is the
  only way in. There is no call that writes a closure without its report, and none that
  writes a report without its closure.


  

    commit(bundle):

      verdict = gate(bundle, head)

      if verdict != ACCEPT: raise CommitRejected

      transaction:

        check parent == current head

        write bundle

        set head to new hash

      # boundary, report, evidence, version land together
  


  

    The claim is conditional and narrow. On Moore report families the closure operator and
    the report family determine each other; outside that class there is a machine-checked
    counterexample. This page does not show that a deployed agent cannot bypass the gate,
    that the attribution layer has been bridged to the closure layer, or that any real system
    has a Moore family. It shows a finite-state reference implementation of the check.
  






  
What it means

  
Strip the examples away and the object is small: a boundary, a description of that
  boundary, and a rule that will not let the description drift off the boundary. Nothing in the
  machine observes itself, and nothing in it is asked to be sincere. The check is structural —
  evaluated against R1–R7 inside the same transaction that would write the state.


  
What the toy is for: showing that the stale state is not a lapse of effort but a location in
  the state space. If settling a boundary and describing it can be split into two moments, a
  system can stand inside that gap, and no amount of honesty within either moment closes it.
  Closing the gap is a design constraint, not a virtue.


  
What it is not: an analogy for anything psychological, a theory of self-knowledge, or a claim
  that a deployed agent already runs this way. It is the smallest finite object in which one
  question — is this report still about this boundary? — is settled by computation rather than by
  narration.
