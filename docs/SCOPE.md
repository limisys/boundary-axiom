# Repository scope

This repository is the public code/evidence release for the Boundary Programme.
It is **not** the paper repository and not the full author workspace.

## Included

- `lean/`: 56-file development body (B line 55 + A module `BoundaryTheory` 1),
  single entry `BoundaryProgramme.lean`.
- `vendor/CausModel/`: 15-file categorical dependency, source only.
- `scripts/`: build, counts, claim index, static audit, axiom check, independent
  numerical reproduction, CI and public scan.
- `docs/`: scope, counts, claims, merge record, DAG static artifacts.
- `data/`: machine-readable counts, claim index, audit results, axiom output,
  reproduction results.
- Root: README (en/zh), status, verification, provenance, citation, licences,
  mirror policy, Lake configuration.

## Not included

The following remain in the author's local full archive and are deliberately
excluded from the public Git tree:

- `archive/` (superseded/failed/draft Lean variants, old build scripts);
- `logs/` (build/verification logs may contain local paths);
- `docs/rounds/`, `docs/audits/`, `docs/thematic/` (internal research notes);
- `crosscheck/` (depends on an external project path);
- `vendor/Godcore_BoundaryTheory/` (upstream backup; duplicate of
  `lean/BoundaryTheory.lean`);
- `vendor/CausModel/交付/` (delivery logs/mapping tables);
- `scripts/legacy/`, `scripts/z3/`, `scripts/verify_all.sh`,
  `scripts/check_crosslink.sh` (author-local audit paths);
- `MANIFEST.sha256` (full local snapshot); public tree uses
  `MANIFEST.public.sha256`;
- the papers, the website, and `public/boundary-programme`.

Exclusion is not a denial of the content. The full local tree remains the source
of truth; the public repository is the reproducible subset needed to build and
check the formal claims.

## Boundary rules

1. Formal source edits happen in the local unified tree, not in stale copies.
2. Any new `.lean` file must be imported by `BoundaryProgramme`; otherwise the
   entry-coverage check fails.
3. Counts are generated by `scripts/counts.py` and checked against
   `docs/counts.json`; do not hand-copy numbers.
4. Claims are indexed in `docs/claims.yaml`; every formalized claim must resolve
   to a Lean declaration.
5. Public documents must not contain absolute local paths, credentials, private
   review records, or internal audit notes.
