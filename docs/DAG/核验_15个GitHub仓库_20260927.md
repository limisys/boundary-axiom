## #8 专节：DSAC-v2 的许可与论文关联（逐问回答）

**Q1：该仓库到底有没有 LICENSE？** 没有。`https://cdn.jsdelivr.net/gh/Jingliang-Duan/DSAC-v2@HEAD/LICENSE` 三种命名（LICENSE / LICENSE.md / LICENSE.txt）均取不到；GitHub 页面许可字段为空、shields 徽章为 "not specified"。报告所称 `license=none` **正确**。

**Q2：是否真与论文 "Mind Your Entropy / TECRL / DSAC-E" 相关？** 有**间接血缘**，但**不是该论文的代码仓库**：
- 论文确实存在：[arXiv:2511.11592](https://arxiv.org/abs/2511.11592)（2025-10-25 提交；ICML 2026 poster），提出 TECRL 框架与算法 **DSAC-E**，摘要明确写 "develop a practical off-policy algorithm, DSAC-E, by extending the state-of-the-art distributional soft actor-critic with three refinements (**DSAC-T**)"。
- 论文作者含 **Jingliang Duan**，正是 `Jingliang-Duan/DSAC-v2` 的 owner，而 DSAC-v2 仓库自述为 "DSAC-v2; DSAC-T; DASC; Distributional Soft Actor-Critic" → DSAC-E 是在 DSAC-T 之上扩展，故存在"上游代码库"关系。
- **但**：该仓库 README 仅引用 DSAC（IEEE 9448360）与 DSAC-T（IEEE 10858686）两篇论文，**全文未出现** "Mind Your Entropy"/"TECRL"/"DSAC-E"/"trajectory entropy" 任何字样；最后一次 push 为 2025-12-01，即论文挂出后一个多月也未更新。
- 结论：把 `Jingliang-Duan/DSAC-v2` 直接描述为 "Mind Your Entropy / TECRL / DSAC-E 的代码" 属**过度关联**；更准确的说法是"DSAC-E 所扩展的 DSAC-T 的参考实现"。

**Q3：仓库里是否有 DSAC-E 的代码？** 没有。完整文件清单（ungh 文件树）为：`README.md`、`dsac_v1.py`、`dsac_v2.py`、`setup.py`、`run_policy.py`、`DSAC2.0_environment.yml`、`env_gym/*`、`example_train/*`、`networks/{mlp,cnn}.py`、`training/{trainer,evaluator,off_sampler,replay_buffer}.py`、`utils/*`、`results/*`。无任何 DSAC-E / TECRL 模块。`dsac_v2.py` 中的 entropy 仅为标准 SAC 熵项与 `target_entropy` 自动温度调节，**不含**轨迹熵约束（TEC）或熵 Q 函数。

**Q4：是否存在官方 DSAC-E 代码？** 未找到。owner `Jingliang-Duan` 名下仅 4 个仓库：`DSAC-v1`、`DSAC-v2`、`DSAC-v2-StableBaselines3`、`Jingliang-Duan.github.io`；arXiv 论文 v1 的 HTML 全文**无任何 GitHub 代码链接**（仅 LaTeXML 模板链接）。
